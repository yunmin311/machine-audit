# Stage 15 · 残留净化复查

## 目的
清点"删了没删干净"的幽灵层：指向不存在目标的注册、快捷方式、服务、任务、目录。产出 R 系列清单（编号+权限档+动作），**本阶段不执行任何删除**——升级动作走安全分层。

## 子检查（每项独立出清单）

### 15.1 死快捷方式
范围：**全部桌面**（先查清有几个）、用户/公共开始菜单。
方法：`WScript.Shell` COM 逐个 `.TargetPath`，非空且 `Test-Path` 失败 = 死。UWP/AppUserModelID 类 target 为空 → 跳过（不是死，是机制不同）。
注意：开始菜单 .lnk 密集（数百个），先收集后过滤，别逐条刷屏。

**双桌面（v0.8 补充，必须只读核实）**：KFM 未重定向、或曾开启又关闭时，机器上可能同时存在两个 Desktop 目录——`<用户>\Desktop` 与 `<用户>\OneDrive\Desktop`。

- 探明哪个是当前桌面：读 `HKCU:\...\Explorer\User Shell Folders` 的 `Desktop` 值，**不要**用 `[Environment]::GetFolderPath("Desktop")` 单独判断（它可能返回另一个）。
- **三处都要扫**，缺一处就会漏：用户桌面（真实路径）、另一份 Desktop（若存在）、公共桌面 `C:\Users\Public\Desktop`。
- 修/建快捷方式时三处一起处理，否则用户打开的是坏的、你修的是好的，会被判定"没修好"。
- 报告里写清"扫了哪几个桌面、哪个是当前生效的"，别只写"桌面"。

### 15.2 死服务
`Win32_Service.PathName` 解析 exe（引号规则：带引号取首段引号内；不带引号按 ` -`/` /`/` --` 切首段），`Test-Path` 失败 = 死。**裸名（如 wscript.exe）依赖 PATH，直接判死会误报**——先尝试 `Get-Command` 再判。输出含服务名/状态/指向。

### 15.3 死自启与死卸载条目
- Run 键（HKCU/HKLM）：同上解析。
- 卸载表三键：`UninstallString` 解析，过滤 `msiexec`（MSI 永远"存在"）；死条目 = 卸载器不存在的 DisplayName。
- 语义提示：死条目 ≠ 软件没了——可能是搬家（旧路径失效、新路径存在）。输出带"新位置是否存在"列，避免用户误删搬家软件的注册。

### 15.4 死计划任务
`Get-ScheduledTask` 的 Actions.Execute 展开环境变量后 `Test-Path`；PATH 解析误报同 15.2 处理；系统目录下的直接放行。

### 15.5 空壳与孤儿目录
- 零文件目录清单（对照体量测量时的结果）。
- 孤儿候选：安装类目录（Program Files / 用户 Programs / 数据盘 APP 区）对照卸载表 DisplayName 做包含匹配，无匹配者列"候选"——**只列候选不判死**（数据目录/游戏库常无卸载条目），处置交用户。

### 15.6 死防火墙规则
阶段 7 的死路径规则计数与 top 清单在此归档为 R 项（管理员档）。

### 15.7 权限残留：拒绝型 ACL（2026-11-08 新增）

**症状**：用户能看见文件，却删不掉/改不了，弹"你需要来自 <自己> 的权限才能对此文件夹进行更改"。

**成因**：某个程序（常见是 agent 沙箱、备份工具、旧版 OneDrive KFM）在目录根写入了**显式 Deny 规则**，
子目录全部继承。Deny 优先级高于 Allow——所以**即使当前用户是 Owner 且拥有 FullControl，操作照样被拒**。

**检测**（只读）：
```powershell
Get-Acl -LiteralPath <path> | Select-Object Owner,@{n='Deny';e={@($_.Access | Where-Object AccessControlType -eq 'Deny').Count}}
# 有 Deny 且继承栏铺满子目录 → R 项，权限档：管理员
```

**判据**：
- Deny 主体是 `Everyone` 或本人账户，且权限含 `Delete`/`Write`/`DeleteSubdirectoriesAndFiles` → 典型残留
- 同一根上存在陌生沙箱组（如 `*SandboxUsers`）且只有只读权 → 高度怀疑是某工具留下的保护位
- 记录时同时输出「为何会有它」的推测，但**不要替用户决定删不删**——有些是真实的保护位

**处置**（管理员，两段式，先轻后重）：
```powershell
# 轻：精确移除
icacls "<path>" /remove:d "Everyone"
icacls "<path>" /remove:d "<域\用户名>"

# 重：取回所有权 + 重置为继承
takeown /f "<path>" /r /d y
icacls "<path>" /reset /t /c /q
```
处置后必须**实测验证**：在目录内建一个临时文件再删除，成功才算关闭。

**坑**：
- 不要用 `icacls <path> /grant` 加 Allow——Deny 仍在，加了也没用。**必须先移除 Deny**。
- 卷影副本（`System Volume Information`）的拒绝是系统设计，不是残留，别动。
- 这类残留会让脚本的 `Remove-Item` 报"部分操作被中止"，容易被误判成"文件被占用"。

### 15.8 零使用服务/软件（2026-11-16 新增）

**症状**：某服务/常驻程序开机自启、占着内存和端口，但主人早已不用（课程作业、试用软件、
装完就忘的中间件）。

**这是最容易漏的一类残留**——它不在"死服务"清单里（路径都有效、服务正常启动），
也不在"孤儿目录"清单里（数据目录正当存在）。它只是**没人用**。

**四重证据（至少三条成立才判定）**：

| # | 证据 | 采集方式 |
|---|---|---|
| 1 | 服务在跑但**无任何客户端连接** | `Get-NetTCPConnection -LocalPort <端口>` 只有 `Listen`，无 `Established` |
| 2 | 应用日志**自启动后无连接/查询记录** | 读 `.err` / `.log`，通常停在 "ready for connections" |
| 3 | **写入型日志无新记录** | 数据库看 binlog 大小（如长期 198–221 字节 = 空轮转）；Web 服务看 access.log |
| 4 | **项目侧零引用** | 在代码仓里搜连接串/端口/驱动名；注意排除 `node_modules` 与打包产物里的误报 |

**判定为"教学/试用遗留"的典型形态**：
- 数据目录里只有**官方示例库/示例数据**（如 MySQL 的 `sakila`、`world`；PostgreSQL 的 `postgres` 模板库）
- 最后一次真实写入是几个月前，此后只有开机轮转
- 防火墙却仍显式放行端口（装的时候随手加的，没人回收）

**处置**（三档，按可逆性）：
1. 停服务 + 改手动启动 —— 立刻释放内存与端口，程序和配置全保留
2. 补 `bind-address=127.0.0.1` / 删防火墙放行规则 —— 保留服务但关掉暴露面
3. 卸载 + 删目录 + 归档数据 —— 收益最大

**必须同时报告的资源口径**：
- 内存用**私有提交**（`PrivateMemorySize64`），不是工作集
- 磁盘要分**程序目录**（常在系统盘）与**数据目录**（可能已被迁到数据盘）
- 端口暴露面单独一行：监听地址（`::` 还是 `127.0.0.1`）+ 防火墙规则（Profile 是否含 Public）

**坑**：
- 服务进程与原监听进程可能不是同一个 PID（Windows 服务常见父/子结构），
  以 `Get-NetTCPConnection` 的 `OwningProcess` 为准去查真实进程。
- "零连接"不等于"可以删"——要区分**没人用**与**定时任务才用**（查计划任务）。
- 卸载后 `net stop` / `sc delete` 可能需要管理员；MSI 卸载退出码 3010 表示"需重启"，不是失败。

## 输出 schema
`## 残留专项`：R 表（编号/类别/数量/明细/权限档/建议动作），分类小计，与上轮 R 数量 diff（净化进度）。全部建议动作默认挂起，等拍板门。

## 常见坑
- 快捷方式 target 为空 ≠ 死（UWP 机制）。
- 服务路径带参数：引号规则拆错会把参数当路径。
- 卸载表里 InstallLocation 缺失很常见——以 UninstallString 为准。
- 正在运行的软件可能在扫描间隙更新目录——快照语义。
