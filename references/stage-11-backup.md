# Stage 11 · 备份合规

## 目的
回答：这台机器上的核心资产，坏了能不能回来？两块：代码仓库的 Git 合规、非代码资产（照片/文档/媒体）的 3-2-1 达标。

## 标准动作
1. **Git 仓库扫描**（project-doctor.ps1 承载）：每个仓 `remote -v` / `status -sb`（ahead/behind/gone）/ `status --porcelain` 计数 / `log -1` 日期。分级：见判定节（备份事实链：无远端/缺目标分支 = 该仓 D 级；是否升级 P0 取决于仓内是否有唯一资产）。
2. **3-2-1 评估**（对 overlay `assets` 声明的核心资产目录）：3 份副本？2 种介质？1 份异地/离线？0 错误=定期恢复演练？——按"达标/缺位"逐项给结论。缺外置冷备对**核心不可再生资产** = P0（资产级判断，需先确认唯一性与核心性，非普遍标签）。
3. **备份代数治理**：识别备份目录（名字含 backup/备份/快照 + 日期后缀模式），每类列代数与时间跨度；建议轮转规则（保留最近 3 代）。
4. **备份有效性抽查**：备份不是"存在"而是"能恢复"——抽查最近一代的 2-3 个文件可读性/哈希一致（只读抽验）。
5. **File History / 系统还原点**：配置状态查询（还原点计划间隔未配置=回滚能力存疑，P2）。

## 判定（v0.6.1：严重度跟随资产影响，非普遍标签）
- 唯一副本的核心资产（照片原片/账套/客户交付物）无第二介质 = **P0**（资产级判断，需先确认"唯一"与"核心"）。
- git 仓无远端 = 该仓的同步缺口（doctor 记 D）；是否升级 P0 取决于仓内是否有唯一资产——**git 同步状态 ≠ 资产备份状态**，勿以同步分替代备份结论。
- 本地领先远端大量提交 = P1；先修网络根因再推（联动阶段 16）。

## 坑
- 备份目录"存在"≠"有效"——时间戳最新的一代才代表 RPO（恢复点目标）。
- git ahead 计数含 merge commit，别双算。
- 网盘"同步"不是"备份"——删除会同步删除；写报告时明确区分 sync 与 backup 语义。
