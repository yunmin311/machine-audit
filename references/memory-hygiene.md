# Stage 18 · 记忆与文档卫生（memory hygiene）

> **核心定位**：防止 agent 产出的 Markdown 与会话日志线性膨胀（每轮必写、只增不并、无退役）引发检索成本与决策污染。本阶段关注信息可用性（不替 `stage-02` 救急磁盘空间）；采用 **"追加为主 + 定期蒸馏 + 归档不删史"** 文件系统机制，不引入额外数据库。

## 1. 五层寿命模型（按衰减速度分层）

判据（30 天后还有用吗）：**有用且为结论 → L3；有用但为过程 → L2；仅当时有用 → L1 或 L4。**

| 层 | 内容 | 典型位置 | 寿命 | 到期动作 |
|---|---|---|---|---|
| **L0 原始会话** | 对话全文、tool 调用 | `.workbuddy/sessions`、`.zcode/cli/db`、`.codex/sessions` | 7–30 天 | 压缩归档（`tar.xz`），保留索引 |
| **L1 工作日志** | `memory/YYYY-MM-DD.md` | agent `memory/` 目录 | **30 天** | **先蒸馏进 MEMORY.md，再删原文件** |
| **L2 阶段报告** | 审查报告、执行记录 | `<归档目录>/reviews/` | 90 天 | 打包归档 + `ARCHIVE-INDEX.md` 留一行 |
| **L3 知识沉淀** | 结论、规则、偏好 | `MEMORY.md`、`references/` | 永久 | 只合并去重，永不删除 |
| **L4 一次性草稿** | 中间分析、试算草稿 | 任意临时位置 | **会话结束** | 合并进正式产物，或直接删 |

## 2. 三种触发与三档动作

| 触发 | 条件 | 强度 | 动作 |
|---|---|---|---|
| **软触发** | 每 **15 轮**对话或任务交付里程碑 | 建议 | 汇总文档增量与处置建议等确认（里程碑应做减法并稿） |
| **硬触发** | 单目录 MD > **200** 份、单文件 > **3,000 行** 或卷剩余 < **15%** | 强制 | 必须给出处置方案再继续主任务 |
| **周期触发** | 每周一次 | 建议 | 跑 `powershell -Command "& '.\scripts\probe.ps1' -Action docs -Roots @('<目标>')"` 发布 diff |

**按可逆性从高到低执行，严禁跳级**：
1. **蒸馏（distill，默认）**：同主题多份合成 1 份，留结论/决策/未决/证据路径（文件+行号/命令位置），推翻的判断留一行`"曾判 X，因 Y 改 Z"`；**蒸馏 ≠ 摘要**，不得压缩后结论仍散落。
2. **压缩归档（archive，L0/L2）**：`tar.xz` 打包 + 更新 `ARCHIVE-INDEX.md`（包名/时间范围/一句话内容/解包命令）后删原文件。
3. **删除（仅限 L4 草稿与已蒸馏 L1 日志）**：S 级唯一副本、未归档报告与 L3 知识沉淀一律不进删除通道。

## 3. 安全边界与写入闸门

- **执行边界**：① **先蒸馏并核对再删除**；② 删除走同盘 `_quarantine/` 14 天冷却（沿用 `references/execution-safety.md`，宽限期脚本尚未实现，到期人工复核后再清）+ `operations.jsonl` 计 sha256/原路径；③ git 已提交文档通过 `git` 退役，不动文件系统直删；④ 不动 S 级资产与静默删报告。
- **三个写入闸门**：① `"值得写吗"三问`（3 个月后还有人看？有人据此决策？能并进既有文件？——任一答"否"不新建）；② **能追加不新建**（文件数膨胀比单文件增长更危险）；③ **结论与过程分离**（过程入 L2 90 天退役，结论入 L3 永久）。

## 4. 与磁盘应急边界、输出 schema 与坑

| 维度 | 磁盘应急（`stage-02`） | 文档卫生（本阶段 `18`） |
|---|---|---|
| 对象与关注 | 缓存/大文件 · 磁盘空间够不够 | 文档/日志/报告 · 信息能否检索复用 |
| 触发与动作 | 卷 `<10%` · 删/移/改配置（紧急可促 L1/L2 提前归档，禁动 L3） | 15 轮/里程碑/`>200` 份 · 蒸馏/归档/退役 |

**输出 schema（`## 文档卫生`）**：① 增量表（新增 MD 数/体量/Top3 目录）→ ② L0–L4 分层盘点与上轮 diff → ③ 建议动作表（对象/层/动作/预计减量/可逆性）→ ④ 一句话最急处置。
**常见坑**：把蒸馏做成摘要；只扫项目目录漏扫 `.workbuddy`/`.codex`/`.zcode` 会话区；删报告未留索引；里程碑当天狂写新稿；误以为 git 提交了即可免整理。
