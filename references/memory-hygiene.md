# Stage 18 · 记忆与文档卫生（memory hygiene）

> **解决什么问题**：agent 每轮对话都可能产出 Markdown。几百轮之后，文档数量呈线性膨胀——
> 报告、日志、中间稿、分析稿互相覆盖同一件事，人找不到结论，磁盘被吃掉，下一次 agent 还要
> 重读一堆过期内容。**这不是磁盘问题，是记忆治理问题。**

---

## 1. 为什么必须有这一阶段

**实测（某台机器，2026-11-07）**：

| 位置 | MD 文件数 | 说明 |
|---|---:|---|
| `<项目根>`（排除 node_modules/.git） | **10,908** | 项目侧文档 |
| `.workbuddy`（排除 plugins） | **4,552** | 会话与工具产物 |
| 单一项目文档膨胀样例 | 248 | 同一主题多轮迭代报告反复拷贝 |

**膨胀的三个机制**（都不是"agent 不听话"，是流程缺陷）：
1. **每轮必写**：没有"这一轮不值得写"的判据，于是全都写。
2. **只增不并**：第二轮报告复述第一轮结论，而不是引用——于是同一事实有 N 个版本。
3. **无退役**：唯一的清理动作是"人忍不了了手动删"，既不定期也不可预期。

**后果排序**：先是人找不到结论（认知成本）→ 再是 agent 上下文被过期内容污染（决策质量）→
最后才是磁盘（本阶段不负责磁盘，那是 stage-02b）。

---

## 2. 五层寿命模型

按"信息衰减速度"分层，而不是按"重要程度"。**越靠上越短命，越靠下越稳定。**

| 层 | 内容 | 典型位置 | 寿命 | 到期动作 |
|---|---|---|---|---|
| **L0 原始会话** | 对话全文、tool 调用 | `.workbuddy/sessions`、`.zcode/cli/db`、`.codex/sessions` | 7–30 天 | 压缩归档（tar.xz），保留索引 |
| **L1 工作日志** | `memory/YYYY-MM-DD.md` | 项目 `.workbuddy/memory/` | **30 天** | **蒸馏进 MEMORY.md，然后删原文件** |
| **L2 阶段报告** | 审查报告、执行记录 | `<归档目录>/reviews/` | 90 天 | 打包归档 + 留一行索引 |
| **L3 知识沉淀** | 结论、规则、偏好 | `MEMORY.md`、`references/` | 永久 | 只做合并去重，不做删除 |
| **L4 一次性草稿** | 中间分析、试算、实验稿 | 任意临时位置 | **会话结束即到期** | 合并进正式产物，或直接删 |

**判据**：一个文件 30 天后还有用吗？
- 还有用且是结论 → L3
- 还有用但是过程 → L2
- 只有当时有用 → L1 或 L4

---

## 3. 三种触发

| 触发 | 条件 | 强度 | 行为 |
|---|---|---|---|
| **软触发** | 每 **15 轮**对话；或里程碑（阶段完成、发布、大重构、审计收官） | 建议 | 报告"当前文档增量 + 建议动作"，等一句话确认 |
| **硬触发** | 单目录 MD > **200**；或单文件 > **3,000 行**；或所在卷剩余 < **15%** | 强制 | 必须给出处置方案才能继续推进任务 |
| **周期触发** | 每周一次 | 建议 | 跑一次扫描（`scripts/doc-hygiene.ps1`），发布 diff |

**里程碑判定**：任务从"进行中"变为"已交付"的那一刻，就是软触发点。此时最该做的是
**把这一轮的过程稿并进结论**，而不是再写第 9 份报告。

---

## 4. 三档动作

**按可逆性从高到低执行，任何一档都不许跳级。**

### 4.1 蒸馏（distill）—— 默认动作

把同一主题的 N 份文档合成 1 份。**保留**：结论、决策、未决问题、证据路径。
**丢弃**：过程叙述、重复的上下文复述、已被推翻的中间结论。

```
8 份 review-N.md（11.6 万字符）
  → 1 份「复核结论与关闭清单」（约 3,000 字）+ 各轮报告降级为附录
```

**蒸馏的最低标准**：
- 每条结论必须能追到原始证据（文件路径 + 行号 / 命令输出位置）
- 被推翻的结论要留一行"曾判定 X，因 Y 改为 Z"——**这是防回溯失忆的关键**
- 蒸馏 ≠ 摘要。摘要是"压缩文字"，蒸馏是"提取可复用的判断"

### 4.2 压缩（archive）—— L0 / L2 的默认动作

`tar.xz` 打包 + 一份索引（`ARCHIVE-INDEX.md`：包名 / 时间范围 / 内容一句话 / 解包命令）。
压缩后**原文件删除**，但在索引里留一行，保证"以后想找能找到"。

### 4.3 删除 —— 仅限两类

1. **L4 一次性草稿**（会话语境消失即无价值）
2. **已蒸馏完成的 L1 日志**（内容已进 MEMORY.md）

**除此以外不删。** S 级唯一副本、报告原文、知识沉淀，一律不进删除通道。

---

## 5. 安全边界

| 规则 | 理由 |
|---|---|
| **先蒸馏，后删除** | 顺序颠倒就是数据丢失。蒸馏产物未通过比对，不许删源 |
| **14 天冷却区** | 删除类文件先移 `_quarantine/`，14 天后二次确认才清空（沿用 execution-safety.md；宽限期管理尚未脚本化，当前手工执行） |
| **哈希登记** | 每条删除记录 sha256 + 体量 + 原路径，写入 `operations.jsonl` |
| **不动 git 里的已提交内容** | 仓库内文档的退役走 commit，不走文件系统删除 |
| **不动 S 级资产** | 照片原片、笔记库、账套、交付物——只归档不删除 |
| **报告类永不静默删除** | 即使过期，也必须经过 L2 打包 + 索引 |

## 6. 写入侧的纪律（比清理更重要）

**清理是亡羊补牢，少写才是治本。** 三个写入闸门：

1. **"值得写吗"三问**：这个结论三个月后还有人看吗？有人会为它做决策吗？它能不能并进已有文件？
   三问有一问答"否"，就不新开文件。
2. **能追加不新建**：同一主题默认追加到既有文档末尾（带日期小标题），而不是 `report-v2.md`。
   **文件数增长是坏味道，行数增长不是。**
3. **结论与过程分离**：过程写在报告里（L2，90 天退役），结论写进 MEMORY.md（L3，永久）。
   **不要为了"留痕"把过程塞进永久层。**

## 7. 与磁盘应急（stage-02b）的边界

| | stage-02b 磁盘应急 | 本节 stage-18 |
|---|---|---|
| 关心 | 空间够不够 | 信息能不能用 |
| 对象 | 缓存、临时、大文件 | 文档、日志、报告 |
| 动作 | 删 / 移 / 改配置 | 蒸馏 / 归档 / 退役 |
| 触发 | 卷剩余 <10% | 轮次 / 里程碑 / 单目录 200 份 |

**交叉点**：磁盘告急时可以临时提高退役力度（L2 提前打包、L1 提前蒸馏），但**不许把 L3 拖进
删除通道**——那是拿记忆换空间，代价最高。

---

## 8. 输出 schema

`## 文档卫生`：四段

1. **增量表**：本轮/本周新增 MD 数、体量、集中在哪三个目录
2. **分层盘点**：L0–L4 各层文件数与体量，与上轮 diff
3. **建议动作表**：对象 / 层 / 动作（蒸馏/压缩/删除）/ 预计减量 / 可逆性
4. **一句话结论**：现在最该做的一件事是什么

## 9. 参考实现取舍（为什么这样设计）

调研了当前主流的 agent 记忆方案，本阶段的选择理由：

| 方案 | 做法 | 为什么不直接用 |
|---|---|---|
| **MemGPT / Letta** | 三层（core / recall / archival），agent 自行换页 | 依赖工具调用与数据库，本场景是"文件 + git"，不引入基础设施 |
| **Mem0** | 每轮从对话抽取事实，**改写**旧记忆 | 改写会丢"当时为什么那么判断"，不可追溯——本场景要审计链 |
| **Zep / Graphiti** | 双时态知识图谱，**只追加不修改** | 方向对（保留历史），但需要图数据库；本场景用"追加 + 定期蒸馏"近似实现 |
| **Markdown + git（MemFS 思路）** | 记忆就是文件，人可读、git 可溯 | **采用**：零依赖、人可审、天然可回退 |

**结论**：采用 **"追加为主 + 定期蒸馏 + 归档不删史"**——接近 Zep 的时态观，落在 Markdown 上。
这也是本技能一贯的取向：**不引入新基础设施，用文件系统本来的能力解决问题。**

## 10. 常见坑

- **把"蒸馏"做成"摘要"**：压缩了字数，但结论仍散落各处——等于没做。
- **只清项目不清 agent**：`.workbuddy` / `.codex` / `.zcode` 的会话与产物往往比项目文档多几倍。
- **删了报告留了索引缺失**：三个月后想找"当时为什么决定不装 X"，找不到就等于没发生过。
- **在里程碑当天狂写报告**：那是文档膨胀的最高发时刻。里程碑应该做减法。
- **以为 git 提交了就安全**：仓库变大会拖慢 clone 与搜索；git 不是免于整理的许可证。
